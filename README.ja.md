# Shinkansen-Nozomi 🚄

[繁體中文](README.md) | [日本語](README.ja.md)

高速でスムーズなウェブページ翻訳ブラウザ拡張機能。Chrome と Firefox に対応。Google Gemini を使って外国語ページを繁体字中国語／簡体字中国語／日本語に翻訳し、テキストをその場で置き換え、ページの元のレイアウトを保持します。

名前は新幹線最速の「のぞみ号」に由来し、高速・安定・スムーズな読書体験を象徴しています。

> **本プロジェクトは主に Firefox 拡張機能に注力しています。Chrome 拡張機能については原作者の [jimmysu0309/shinkansen](https://github.com/jimmysu0309/shinkansen) をご参照ください。**

> **本プロジェクトは [jimmysu0309/shinkansen](https://github.com/jimmysu0309/shinkansen) からフォーク**（原作者：Jimmy Su）し、Firefox 対応・多言語インターフェース（繁中／簡中／日本語）・選択範囲翻訳などの機能を追加して独立開発しています。

> [最新版 zip をダウンロード](https://github.com/r404r/shinkansen/releases/latest) · [変更履歴](CHANGELOG.md)

## 最近の主なアップデート

- **AI スマート文分割**を追加：YouTube の自動生成字幕を AI が文脈に基づいて再分割し、翻訳字幕をより自然で読みやすく
- **バイリンガル対照モード**を追加：原文＋訳文を並列表示
- **中国語用語の禁止リスト**を追加：LLM に「视频 / 软件 / 数据」などの中国大陸用語を使わないよう明示的に指示（繁体字中国語モード専用）
- **カスタム AI モデル**機能を追加：OpenRouter / Claude / DeepSeek / Ollama ローカルなど、数百種類のモデルに接続可能

## このプロジェクトの目的

既存のウェブ翻訳ツールは、個人の閲覧内容をサードパーティのサーバーに送信する必要があり、プライバシーの管理が難しい状況です。Shinkansen-Nozomi は設計の最初からプライバシーを核心に据えています。すべての設定とデータはお使いのコンピュータにのみ保存され、ご自身で用意した Gemini API Key で Google に直接接続する以外、いかなるデータも第三者に送信しません。ソースコードは完全公開されており、誰でもその安全性を検証できます。

## パフォーマンステスト

英語版 Wikipedia の Taiwan 記事（1,000段落超）でストレステストを実施しました。メモリ使用量は増加せず（日本語は英語より簡潔なため）、翻訳中もページが重くならず（95%以上の時間が API 応答待ちで、PC はほぼ追加計算をしない）、翻訳完了後もページ構造はクリーンなまま。最安モデルでページ全体を翻訳しても API 費用は 0.08 ドル未満（約12円）で、翻訳済みの内容は自動キャッシュされるため、次回アクセス時に再課金されません。詳細なテストデータは [PERFORMANCE.md](PERFORMANCE.md) をご覧ください。

## 主な機能

- **ウェブページのレイアウトを保持**：テキストをその場で置き換え、フォント・サイズ・色・レイアウトを保持。リンクはクリック可能、太字・斜体もそのまま
- **単一言語カバー／バイリンガル対照の2モード**（v1.5.0〜）：ポップアップでワンクリック切替——「単一言語カバー」はその場で置き換え、「バイリンガル対照」は原文を保持しつつ訳文を新段落として追加。バイリンガルモードでは4種類の視覚マーク（薄い背景色／左側バー／破線下線／なし）から訳文段落の表示スタイルを選択可能
- **段階的翻訳**：バッチ送信・逐次注入。ページが段落ごとに翻訳され、全体の完了を待つ必要なし
- **3つの翻訳エンジン**：Gemini（AI 翻訳・最高品質・API Key 必要）+ Google Translate（非公式無料エンドポイント・API Key 不要・より高速）+ **カスタムモデル**（v1.5.7〜、OpenAI 互換エンドポイント、OpenRouter / Together / DeepSeek / Groq / Ollama ローカルなど数百種類のモデルに対応）、用途に応じて自由に切替
- **3組のカスタマイズ可能なショートカット**：`Alt+A` / `Alt+S` / `Alt+D` にそれぞれ翻訳プリセット（エンジン＋モデル＋ラベル）を割り当て、ページ内容の重要度に応じてワンキーで異なるエンジンを選択（例：精読には Flash、流し読みには Google MT）。詳細は下記「翻訳ショートカットキーとプリセット」セクションを参照
- **選択範囲翻訳**（Nozomi v1.6〜）：ページ上のテキストを選択してショートカットを押すと、選択範囲内の段落のみ翻訳。特定の段落だけ翻訳したい時に便利
- **YouTube 字幕リアルタイム翻訳**：YouTube の字幕を自動検出し、リアルタイムで翻訳。字幕スタイルは YouTube ネイティブと完全一致。詳細は下記「YouTube 字幕翻訳」セクションを参照
- **固定用語集**：翻訳対照表をカスタマイズし、特定の用語を指定した訳語に固定。グローバルとドメイン専用の2層をサポートし、ドメインルールがグローバルの同名エントリを上書き。詳細は下記「固定用語集」セクションを参照
- **禁止用語リスト**（v1.5.6〜）：編集可能な禁止用語対照表（デフォルト25件、视频／软件／数据／网络／质量／用户など頻出の問題用語をカバー）。system prompt の末尾に高優先度ブロックとして注入し、訳文に左列の用語を使用しないよう明示的に指示。詳細は下記「禁止用語リスト」セクションを参照
- **全文用語集の統一**（デフォルトはオフ）：人名が多い長文に特に有効。同一の人名や固有名詞の翻訳を前後で統一。詳細は下記「用語集の統一」セクションを参照
- **翻訳キャッシュと即時節約レポート**：2層キャッシュメカニズム（ローカルキャッシュ + Gemini implicit cache）。翻訳完了後の通知メッセージに cache hit rate と実際の節約額をリアルタイム表示。詳細は下記「翻訳キャッシュと費用計算」セクションを参照
- **3次元レートリミッター**：RPM / TPM / RPD スライディングウィンドウで Gemini API のクォータに自動対応
- **使用量追跡**：各翻訳のトークン数と費用を記録。グラフと CSV エクスポート付き
- **訳文編集**：翻訳完了後、ページ上で直接訳文を修正可能。PDF 印刷や Readwise Reader への取り込み時に、翻訳が不自然な箇所を手動で修正するのに便利
- **タブ間翻訳継続**（v1.4.11〜）：タブ A でショートカット翻訳後、A からリンクで新しいタブ B を開く（Cmd（Mac）/ Ctrl（Windows）＋クリック、`target="_blank"`、`window.open` を含む）と、B が自動翻訳され同じプリセットを継承。新タブからさらに新タブを開いても継続
- **指定サイト自動翻訳**：設定ページによく見るドメインを追加すると、そのサイトを開いた際に自動翻訳（翻訳通知に `[自動翻訳]` と表示）
- **原文復元**：同じショートカットキーで原文に切替。いつでも対照可能
- **Google Docs 翻訳**：Google Docs を自動検出し、翻訳可能な閲覧版を開いて翻訳（詳細は下記を参照）

## インストール方法

**Chrome — 推奨：Chrome Web Store**

[Chrome Web Store のインストールページ](https://chromewebstore.google.com/detail/shinkansen/pnhmlecoofeoofajcjenndnimhbodhlg)にアクセスし、「Chrome に追加」をクリックするだけです。

**Chrome — 開発版（パッケージなしで読み込み）**

1. Chrome を開き、アドレスバーに `chrome://extensions/` と入力して Enter
2. 右上の「デベロッパーモード」をオン
3. 「パッケージ化されていない拡張機能を読み込む」（Load unpacked）をクリック
4. 本プロジェクトの `shinkansen/` フォルダ（または `build/chrome/` ビルド成果物）を選択
5. 拡張機能一覧に Shinkansen が表示され、ツールバーに固定できます

**Firefox — 開発版（一時的な読み込み）**

1. Firefox を開き、アドレスバーに `about:debugging#/runtime/this-firefox` と入力
2. 「一時的なアドオンを読み込む」（Load Temporary Add-on）をクリック
3. `build/firefox/manifest.json` を選択（事前に `npm run build:firefox` を実行）
4. 注意：一時的に読み込んだ拡張機能は Firefox の再起動後に消えます

## 初期設定

1. Gemini API Key を申請 — 詳細は [API Key 申請ガイド](API-KEY-SETUP.md) を参照
2. ツールバーの Shinkansen-Nozomi アイコン → 「設定」をクリック
3. Gemini API Key を貼り付け
4. デフォルトモデル `gemini-3-flash-preview`、Service Tier `DEFAULT`
5. その他のパラメータは必要に応じて調整（温度、バッチ段落数、文字バジェットなど）

## インターフェース言語設定

Shinkansen-Nozomi は3つのインターフェース言語に対応。翻訳の対象言語とプロンプトも同時に切り替わります：

| 言語 | 翻訳対象 | プロンプトの文脈 |
|------|---------|-----------------|
| 繁体字中国語（デフォルト） | 台湾繁体字中国語 | 台湾の用語・通用訳名 |
| 簡体字中国語 | 大陸簡体字中国語 | 大陸の標準用語・通用訳名 |
| 日本語 | 日本語 | 自然な日本語表現・日本の通用訳名 |

切替方法：設定 → 一般設定 → インターフェース言語

## 使い方

- **手動翻訳**：ツールバーアイコン → 「このページを翻訳」
- **翻訳ショートカット**（v1.4.12〜 3組）：
  - `Option+A`（macOS）/ `Alt+A` — デフォルト Gemini Flash Lite（低コスト）
  - `Option+S` / `Alt+S` — デフォルト Gemini Flash（高品質、日常利用におすすめ）
  - `Option+D` / `Alt+D` — デフォルト Google Translate（無料、API Key 不要）
  - 3組のキー・エンジン・モデル・ラベルはすべて設定ページの「翻訳ショートカット」セクションでカスタマイズ可能
  - 翻訳済み状態でいずれかのショートカット → 原文に戻す
  - 翻訳中にいずれかのショートカット → 翻訳キャンセル
- **選択範囲翻訳**（Nozomi v1.6〜）：マウスでページ上のテキストを選択してショートカットを押すと、選択範囲内の段落のみ翻訳（ページ全体は翻訳しない）。翻訳通知に `[選択翻訳]` プレフィックスが表示される。テキスト未選択時にショートカットを押すとページ全体を通常翻訳
- **YouTube 字幕翻訳**：英語字幕付きの動画を開き、CC がオンになっていることを確認し、ツールバーアイコン → 「YouTube 字幕翻訳」スイッチをオン
- **指定サイト自動翻訳**：設定ページの「自動翻訳ウェブサイト」リストにドメインを追加すると、そのサイトに入った際に自動翻訳（翻訳通知に `[自動翻訳]` プレフィックスが表示）
- **固定用語集**：設定ページの「用語集」タブで対照エントリを追加すると、翻訳時に指定した訳語が強制適用
- **用語集の統一**：ポップアップまたは設定ページで「用語集の統一」をオンにすると、長文翻訳時にまず固有名詞対照表を作成
- **訳文編集**：翻訳完了後、ポップアップで「訳文を編集」をクリックすると、ページ上の訳文を直接修正可能

## ショートカットキーとプリセット

v1.4.12 より、3組のカスタマイズ可能な翻訳プリセットを提供。それぞれにショートカットキーが割り当てられています：

| ショートカット | デフォルトエンジン | デフォルトモデル | 適した用途 |
|--------------|-------------------|-----------------|-----------|
| `Alt+A` / `Option+A` | Gemini | Flash Lite（$0.10 / $0.30） | 手軽な翻訳、最もコスト重視 |
| `Alt+S` / `Option+S` | Gemini | Flash（$0.50 / $3.00） | 日常の読書、最高のコストパフォーマンス |
| `Alt+D` / `Option+D` | Google Translate | — | API Key 不要・高速・完全無料 |

**設定ページの「翻訳ショートカット」セクションでカスタマイズ可能**：各プリセットのエンジン（Gemini / Google Translate / カスタムモデル）、モデル（Flash Lite / Flash / Pro / カスタム）、表示ラベルをすべて変更できます。

**ショートカットキーの変更**：

- **Firefox**（Nozomi v1.7〜）：設定ページのショートカットキーバッジを直接クリックして編集モードに入り、新しいキーの組み合わせを押すと即座に反映。`Alt+`、`Ctrl+`、`Shift+`、macOS の `Command+` 修飾キーに対応。`Esc` でキャンセル。
- **Chrome**：ブラウザの API 制限により、拡張機能からショートカットキーを変更できません。`chrome://extensions/shortcuts` ページで手動設定してください。

**統一されたキャンセル／復元動作**：

- 翻訳中にいずれかのショートカットを押す → 即座に翻訳をキャンセル
- 翻訳済み状態でいずれかのショートカットを押す → 原文に復元（どのプリセットで翻訳したかは問わない）

**タブ間翻訳継続**（v1.4.11〜）：タブ A でショートカット翻訳後、A からリンクで新しいタブ B を開く（Cmd（Mac）/ Ctrl（Windows）＋クリック、`target="_blank"` または `window.open`）と、B が自動翻訳され同じプリセットを継承——リンクをたどって読み進める際に毎回ショートカットを押す必要がありません。新タブからさらに新タブを開いても継続。手動で URL を入力した場合やブックマーク・外部アプリから開いたタブは継承しません（openerTabId が空のため）。いずれかのショートカットで原文に戻す操作は現在のタブにのみ影響し、ツリー内の他のタブには影響しません。

## Google Translate エンジン

v1.4.0 より Google Translate を第2の翻訳エンジンとしてサポート：

- **API Key 不要**：Google の公開非公式 web エンドポイント（`translate.google.com` と同じオリジン）を使用。完全無料
- **より高速**：機械翻訳の応答時間は通常 LLM より短い
- **品質のトレードオフ**：文法の自然さや語感は Gemini にやや劣るが、純粋な技術コンテンツ（ニュース、仕様書）には十分
- **リンクとフォーマットを保持**：`<a>`、`<b>`、`<small>` などのセマンティックタグを特殊マーカーで保護し、翻訳後に構造を完全復元（ページ全体の `<span>` が壊れることはない）
- **費用ゼロ、Gemini クォータに影響なし**：ただし非公式エンドポイントのため SLA 保証なし。Google 側の変更に追従が必要な場合あり

適した用途：英語フォーラム、ニュース、商品ページなど「意味が分かればOK」のコンテンツを大量に閲覧する場合は Google MT で API 費用を節約。精密な翻訳（文学、学術論文、固有名詞の処理）が必要な場合は Gemini に切替。

## Bing Translate 翻訳エンジン

Nozomi 独自機能。Microsoft Bing の非公式翻訳エンドポイントを使用。Google Translate と同様ですが、重要な利点があります：

- **中国本土で利用可能**：`cn.bing.com` は中国本土で正常に動作します（Google Translate はブロックされています）
- **API キー不要**：完全無料
- **自動ドメイン検出**：デフォルトの `auto` モードでは `www.bing.com` を試し、失敗した場合は自動的に `cn.bing.com` にフォールバック
- **品質は Google Translate と同等**

設定方法：設定ページの「翻訳ショートカット」で任意のプリセットエンジンを「Bing Translate」に変更。

## Google Docs 翻訳

Google Docs の編集画面は Canvas でテキストをレンダリングするため、一般的なウェブ翻訳拡張機能はその内容にアクセスできません。Shinkansen-Nozomi は Google Docs ページを自動検出し、以下のフローで処理します：

1. Google Docs の編集ページで `Option + S`（またはポップアップの「このページを翻訳」）を押す
2. Shinkansen-Nozomi が自動的に新しいタブで同じドキュメントの「モバイル閲覧モード」（mobilebasic）を開く
3. 新しいタブの読み込み完了後、自動的に翻訳を開始（再度押す必要なし）

注意事項：対象ドキュメントの閲覧権限が必要です。「モバイル閲覧モード」は読み取り専用で、元のドキュメントに影響しません。

## YouTube 字幕翻訳

英語字幕付きの YouTube 動画を開き、CC がオンになっていることを確認し、ツールバーの Shinkansen-Nozomi アイコンをクリックすると、ポップアップに「YouTube 字幕翻訳」スイッチが表示されます。オンにすると、動画の再生に影響を与えることなく字幕が逐次翻訳されます。スタイルは YouTube ネイティブ字幕と完全一致です。

YouTube の英語動画をよく視聴する場合は、設定ページの「YouTube 字幕」タブで自動翻訳をオンにすると、動画ページに入った際に字幕翻訳が自動で開始され、毎回手動でスイッチを切り替える必要がなくなります。

### AI スマート文分割（upstream v1.7〜、自動生成字幕専用）

YouTube の自動生成字幕（人工字幕がない動画、CC マークが auto-generated）は元々「**時間で分割**」されており、「文で分割」されていません——各字幕は英語1〜3語のみで句読点なし、1つずつ翻訳すると文脈が完全に失われ、訳文は細切れで読みにくくなります。

Shinkansen v1.7 より、自動生成字幕に専用フローを導入：

- **AI による文の再構成**：ASR フラグメント全体を Gemini に送り、AI が文脈に基づいて再分割（短いフラグメントを完全な文に統合、句読点を補完）してから翻訳。字幕が「断片的な単語」から「完全な文」に変わります。
- **デフォルトは「ハイブリッドモード」**：まずローカルのヒューリスティックで高速分割して表示（即座に表示、待ち時間なし）、バックグラウンドで同時に AI 分割を実行し、完了後により精緻なバージョンに置換——速度と品質を両立。
- **字幕オーバーレイは文全体を安定表示**：独自のオーバーレイで YouTube ネイティブの caption-segment を完全にバイパス（「1文字ずつ表示される」現象を回避）。整文が一括で表示・消去。コントロールバー表示時は自動的に上に移動してプログレスバーとの重なりを回避。
- **オフにも可能**：最低遅延のみを重視し、YouTube の元の分割ロジックで翻訳したい場合は、設定ページの「YouTube 字幕 → AI 文分割モード」のチェックを外してください。

人工アップロード字幕（professional / community-contributed）はこの設定の影響を受けず、従来の1文ずつ翻訳パスを使用します。

### 費用

字幕翻訳とウェブページ翻訳は同じ課金ロジックと使用量追跡を共有。翻訳済みの字幕は自動キャッシュされ、リプレイや既に翻訳済みの区間に戻っても費用はかかりません。AI 文分割モードはオフ時より token 使用量がやや多い（文脈分割用のプロンプトが追加で1回送信されるため）ですが、翻訳の読みやすさが大幅に向上するため、オンを推奨します。

### 注意事項

- 動画に英語字幕が必要（手動アップロードまたは自動生成のどちらでも可）
- 字幕翻訳は独立した system prompt を使用。設定ページの「YouTube 字幕」タブでカスタマイズ可能
- CC がオフの場合、Shinkansen が自動的にオンにします（各動画セッションで1回のみ自動オン。ユーザーが手動でオフにした場合はそれを尊重）
- 動画を切り替えた場合はスイッチを再度オンにする必要あり（または自動翻訳をオン）

## 翻訳キャッシュと費用計算

Shinkansen-Nozomi には2層のキャッシュメカニズムがあり、それぞれ異なる段階でコストを削減します：

**第1層：ローカル翻訳キャッシュ**——翻訳済みの段落は SHA-1 ハッシュをキーとしてブラウザの `chrome.storage.local` に保存されます。次回同じ原文に遭遇した場合（異なるウェブページでも）、直接取得され、API を呼び出さず、費用もかかりません。拡張機能のバージョン更新時にキャッシュは自動クリアされ、新バージョンの翻訳ロジックが古い結果を使用しないようにします。キャッシュが満杯になると、最も長く使用されていないエントリが自動的に淘汰されます（LRU）。

**第2層：Gemini implicit context cache**——Google サーバー側で自動的に処理されます。連続リクエストのプロンプトプレフィックスが同一（例：system prompt + 用語集）の場合、Gemini はそのプレフィックスをキャッシュし、ヒットしたトークンは通常価格の25%のみ課金されます。ユーザー側の設定は不要で、Shinkansen-Nozomi が API レスポンスからヒットデータを自動的に読み取ります。

**翻訳完了後、ページ右下の通知に2行のデータがリアルタイム表示されます：**

- 第1行：`{課金 tokens} tokens (XX% hit)` — 課金トークン数、および Gemini implicit cache のヒット率（ヒットした input tokens が全 input tokens に占める割合）
- 第2行：`${課金金額} (XX% saved)` — 実際の支払額、およびキャッシュ割引なしと比較した節約率

ページ全体のすべての段落がローカルキャッシュでヒットした場合（例：翻訳したばかりのページを再翻訳）、通知メッセージに「全キャッシュヒット・今回は未課金」と直接表示されます。

過去の各翻訳のトークン使用量、費用、cache hit rate はすべて記録され、設定ページの「使用量記録」タブで確認できます。

## 固定用語集

設定ページの「用語集」タブで翻訳対照表をカスタマイズし、特定の原文用語を指定した訳語に固定できます。例えば "Arrow" を常に「アロー」と翻訳させたり、DC Comics 関連サイトでは "Arrow" を「エタリアルデルフィニウムの矢」と翻訳させたりできます。

用語集は2層に分かれています：「グローバル」はすべてのサイトに適用、「ドメイン専用」は指定ドメインでのみ有効。グローバルとドメインに同じ原文エントリがある場合、ドメインルールがグローバルを上書きします。

固定用語集の優先度は自動用語集の統一よりも高くなります。翻訳時、固定用語集の指示は system prompt の最末尾に配置され、LLM が最も高い重みを与えます。用語集を修正した後にキャッシュを手動クリアする必要はなく、Shinkansen-Nozomi が古いキャッシュを自動的に無効化します。

## カスタムモデル（OpenAI 互換エンドポイント）

v1.5.7 より、Gemini と Google Translate の2つの既存エンジンに加えて、OpenAI 互換エンドポイントを1つ接続し、Gemini 以外のモデルを使用できます。例えば：

- **OpenRouter**（`https://openrouter.ai/api/v1`）：1つのエンドポイントで数百種類のモデルにアクセス。Anthropic / Gemini / DeepSeek / Llama / Qwen / Grok / xAI / Mistral 等を含む
- **Together / Groq / Fireworks** などのモデルプロバイダー
- **Ollama ローカル**（`http://localhost:11434/v1`）：自分のオープンソースモデルを実行。コストゼロ・遅延ゼロ
- **OpenAI 本家**（`https://api.openai.com/v1`）

### 設定手順

1. 設定ページの「カスタムモデル」タブを開く
2. 3つの必須フィールドを入力：
   - **Base URL**：例 `https://openrouter.ai/api/v1`（システムが自動的に `/chat/completions` を付加）
   - **モデル ID**：例 `anthropic/claude-sonnet-4-5`（OpenRouter の形式は `provider/model`）
   - **API Key**：対応するプロバイダーの Bearer token。右側の「テスト」ボタンで即座に接続検証可能（約1 token 消費）
3. オプション：翻訳 Prompt（空欄 = 内蔵のデフォルトを使用、デフォルト値は Gemini と同じ）/ Temperature / モデル料金 input / output 単価（USD / 1M tokens；0 = 費用非表示）
4. 保存
5. 「一般設定」タブの「翻訳ショートカット」で、いずれかのプリセットのエンジンを「カスタムモデル」に変更
6. そのプリセットのショートカットで翻訳すると、カスタムモデルのエンドポイントを使用

### 設計のポイント

- **翻訳 Prompt は独立**：カスタムモデルは独自の翻訳 prompt を使用し、Gemini タブの設定は継承しない
- **禁止用語リストと固定用語集は共有**：両タブの設定が自動的に prompt 末尾に注入され、カスタムモデルにも適用。一方を変更すると両方に反映
- **キャッシュは分離**：cache key に base URL ハッシュが含まれ、異なるエンドポイントの同名モデルが互いに汚染しない
- **API Key はクラウドに送信されない**：`customProvider.apiKey` はブラウザのローカルにのみ保存。デバイス間同期やエクスポート JSON の範囲外
- **レートリミッターは不使用**：OpenRouter 等のプロバイダーが自身のクォータを管理。429 バックオフリトライは内蔵

### 思考強度制御（v1.6.18〜）

一部のモデルは「思考モード」（reasoning / thinking）をサポートし、回答前に推論を行います。Shinkansen-Nozomi は統一された5段階制御（auto / off / low / medium / high）を提供し、異なるプロバイダーの API 差異に自動対応（OpenRouter unified reasoning / DeepSeek extra_body.thinking / Claude thinking.type / OpenAI reasoning_effort / Grok / Qwen enable_thinking）。デフォルトは `auto`（パラメータ未送信、プロバイダーに任せる）。

上級ユーザーは「Extra Body JSON」フィールドにカスタム JSON を入力可能。リクエスト body に deep merge され、自動マッピングの上書きやプロバイダー固有のパラメータ追加に対応。

### 制限事項

- 現在、設定できるカスタムモデルは**1組のみ**
- 真の OpenAI 互換である必要あり（`POST /chat/completions` + `Bearer` Authorization + 標準 `messages` 構造 + `usage.prompt_tokens` / `completion_tokens` フィールド）。Anthropic と Gemini の**ネイティブ** API は直接接続不可。ただし OpenRouter 経由であれば可能
- 料金は自分で入力する必要あり。トークン推定はプロバイダーがレスポンスの `usage` オブジェクトで正しく返すことに依存

## 禁止用語リスト

LLM が繁体字中国語に翻訳する際、台湾の慣用語をできるだけ使用しますが、時折「视频」「软件」「数据」「网络」「用户」などの中国大陸用語が出力されることがあります——特に原文が英語（video / software / data / user）の場合、モデルは最も一般的な中国語訳をそのまま使用しがちです。そのため Shinkansen には禁止用語対照表が内蔵されており、左列の用語は絶対に使用不可、右列の用語に置き換えるようモデルに明示的に指示します。

デフォルトリストは25件で、よくある問題用語をカバー：视频→影片、音频→音訊、软件→軟體、硬件→硬體、程序→程式、进程→行程（process）、线程→執行緒（thread）、数据→資料、数据库→資料庫、网络→網路、信息→資訊、质量→品質、用户→使用者、默认→預設、创建→建立、实现→實作、运行→執行、发布→發表、屏幕→螢幕、界面→介面、文档→文件、操作系统→作業系統、その他「剑指→針對」「痛点→要害」「硬伤→罩門」などのスタイル用語も含む。

設定ページの「禁止用語リスト」タブでこのリストを編集できます——よく遭遇する用語の追加・修正・削除が可能。「デフォルトリストに戻す」でデフォルトの25件に復元。各エントリは3列：禁止用語、置換用語、備考（備考は空欄可）。

技術的にはこのリストが `<forbidden_terms_blacklist>` ブロックとして system prompt の最末尾に注入されます。これはプロンプト全体で LLM の注意力が最も高い位置であり、「あらゆるスタイル上の考慮よりも優先」と明示されています。記事自体が中国語用語を論じている場合（例：「中国のテクノロジー用語の変遷」を分析する記事）、prompt はモデルに引用符で原語を保持するよう指示し、合理的なエスケープハッチを提供します。リスト修正後、Shinkansen は古いキャッシュを自動的に無効化するため、手動でキャッシュをクリアする必要はありません。

また、翻訳レスポンスごとに Shinkansen が訳文をスキャンし、禁止リストの用語が訳文に漏れた場合は Debug タブに `forbidden-term-leak` warning を記録（原文と訳文の該当箇所を含む）。漏れたケースを追跡できます——ただし訳文を**自動的に書き換えることはしません**。「中国語表記の好みは prompt で処理し、事後の正規表現置換は行わない」という設計原則に従い、訳文中の正当な引用シーンを誤って破壊することを防ぎます。

> **注意：この機能は繁体字中国語モード専用です。** 簡体字中国語（zh-CN）モードでは禁止用語リストは自動的にスキップされます（大陸用語がそのまま正しい表現であるため）。

## 用語集の統一

LLM は長文翻訳時、前後の人名・地名の翻訳が一貫しないことがあります（例：同一人物の名前が前半では「ジョンソン」、後半では「ジョンスン」に変わる）。「用語集の統一」をオンにすると、Shinkansen-Nozomi がまず全文をスキャンして固有名詞対照表を作成し、その後の翻訳で同一の訳名を遵守させます。

この機能はデフォルトではオフです。特に精密な翻訳が必要な場合（人名が多い報道記事、学術論文など）にのみ手動でオンにすることを推奨します。副作用として、用語翻訳が system prompt の一部の指示をスキップすることがあります——例えば「英語の人名はそのまま保持」と設定していても、用語集をオンにすると一律翻訳されます。また、用語集の作成に追加の API 呼び出しが必要なため、少量のトークン消費と翻訳時間の増加があります。
